# Connect Relay to the real project

Execution brief for the agent that can access the live checkout and Mac workers.
This package is implemented and locally tested; it is not installed in the live
pipeline. The fixture does not qualify any Kalon modules.

## Current objective

For l2audio, DMG-1 has shipped and DMG-2 is the target. Eugene estimates roughly
45 of about 120 modules are complete. Reconcile the current canonical inventory
once. Do not substitute the historical 0/52 campaign for overall progress. In
another project, use its current agreed milestone.

Pieces must be assembled into complete modules. Preserve their exact source
identities, existing accepted evidence, dependency order, current work, normal
playback, immutable releases and all required release functionality.

## Execute

1. Inspect the actual checkout, authoritative instructions, active workers,
   locks and queue. Do not reset local work to the remotely inspected copy or
   launch a second writer. Limit initial reading to the relevant current rules
   and candidate records.
2. Resolve review routing. The inspected Rules V2 says PCM changes get three
   reviews, high-risk changes without PCM changes get one Astra review, and a
   MOVE with byte-identical proof needs no model review. The older module
   runbook still describes three reviews for the broader high-risk category.
   Verify today's governing policy and update stale guidance and executable
   routing together. Preserve required independent review and test gates.
3. Select two real DMG-2 modules with their existing required pieces close to
   ready. Create a Relay manifest with exact piece revisions, relevant
   dependencies, acceptance-policy version, adapter versions and toolchain
   identity. Import valid existing receipts instead of rebuilding accepted
   pieces. Never invent current commits or approvals.
4. Connect thin adapters to the approved scripts. Piece adapters verify/import
   existing work or execute bounded implementation tasks. Assembly combines all
   required pieces into an isolated unit candidate. Tests run its actual checks.
   Review verifies every required independent mark on that candidate, launching
   only genuinely missing reviews. ADAPTERS.md defines the receipt protocol.
5. The batch adapter combines compatible complete module candidates and uses
   the existing integration gate/merge train on that combined source. Retain
   its failure isolation, exact-candidate evidence and publication rules. Start
   in test_only mode. A test receipt must never claim a merge or release.
6. Separate coding slots, native build slots, worktree/file ownership and the
   singleton integration slot. Retain resource, sandbox, process-containment,
   cleanup and spending controls. Relay is not a replacement for those guards.
7. Run the pilot and measure actual eligible-to-worker-launch time, active AI
   time, tests, repeated reviews, and completely integrated modules. Initial
   coordination target: p95 below five seconds when a required slot is free.
   This is a target to verify, not a production measurement or a deadline for
   substantive review.
8. Prove controlled restart recovery without duplicate work, local failure
   isolation, unchanged-evidence reuse and affected-dependency invalidation.
   Then transfer ownership explicitly from the old dispatcher. Reuse the
   approved supervisor where possible. If a new installation needs specifically
   named permission, prepare the exact reviewed change before asking, while
   independent authorized module work continues.

## Make reviews finish

Review a fixed assembled candidate against its existing acceptance contract.
Return consolidated findings; each blocker needs a failed requirement or
material defect, evidence, and a verifiable resolution condition. Follow-up
review covers corrections and affected behavior. New material defects remain
blockers. Optional redesigns must not silently expand release scope.

Preserve historical acceptance while its evidence remains applicable. A new
reviewer or unrelated commit alone is not proof of invalidity. Carry evidence
only where the current gates permit it; never manufacture an exact-head PASS.
The combined candidate still owes integration and DMG qualification.

## Pilot completion

Two real complete modules advance from existing pieces through assembly,
required tests and independent review into the established integration path,
with actual evidence. Routine transitions use zero AI calls. Report the modules
actually integrated, measured handoff times, remaining blockers, running
controller/supervisor identity, and the next automatically runnable work.
Continue toward DMG-2 after the pilot. A running PID, the fixture demo, or green
pieces alone do not meet this completion condition.
