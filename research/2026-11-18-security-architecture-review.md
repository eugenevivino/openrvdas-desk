## 4. Crypto profile | CHANGE

**TOTP HMAC-SHA1 is conditionally acceptable.** The SHA-1 digital-signature restriction does not by itself prohibit HMAC-SHA1. FIPS 140-3 validates a module and its approved services. Check the exact deployed module’s security policy, allowed HMAC keys and site transition policy. Require a random seed of adequate strength, per-account throttling and atomic acceptance of each valid time step only once, including during clock rollback. The six-digit OTP makes those last two controls essential. Scope the claim to the server unless the authenticator is also in the assessed boundary. Prefer HMAC-SHA256 where the pinned authenticator clients support it.

**Keep ECDSA P-384 with SHA-384.** Ed25519 is standardized in FIPS 186-5. Deployment requires EdDSA support in the specific validated module and approved mode. P-384 is a defensible common choice for this fleet. Constrain WebAuthn enrollment to the intended algorithms as well. ## 5. Audit against root | CHANGE

**Yes. Host root can defeat the local design undetected.** A dedicated signer account restricts application administrators. Root controls the event sources, signer invocation, local storage and local verifier. A hash chain can expose edits relative to a trusted head. A locally valid chain can still be incomplete, truncated or replaced. Even a non-exportable signing key cannot establish that every action reached the signer. [Audit design](/private/tmp/deepsignal/desk-main/docs/SECURITY-ARCHITECTURE.md:339)

The defensible guarantee is **detection of a later change to the prefix committed to an independently retained checkpoint**, when an independent verifier checks continuity against that checkpoint and a previously trusted public key. It establishes neither the truth of the original event nor the identity of the human behind a compromised host. A five-minute signing interval gives no five-minute detection bound when checkpoints remain aboard the same host for weeks.

Adopt the MCP design’s independent onboard witness. Have it retain vessel ID, sequence, head hash, signing-key ID and receipt time, and alert from the witness on missing checkpoints. Verify continuity after restarts and key rotations. Retain off-host records where investigators need to reconstruct a lost log. While the witness is unavailable, show the age of the last witnessed head. Describe the unsigned MVP chain as a local integrity check. [Adopted witness requirement](/private/tmp/deepsignal/desk-main/research/2026-11-18-mcp-design.md:337)
