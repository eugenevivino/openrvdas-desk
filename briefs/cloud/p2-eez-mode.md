## Goal
Entering a foreign EEZ without clearance never depends on someone remembering to switch modes. The ship's
position is checked against offline EEZ polygons. Watchstanders are warned before the line. Each instrument
does what the cruise's clearance says: keep logging, quarantine or stop. A one-tap override needs a reason.
Every crossing and action lands in an audit log fit for the cruise report and the foreign observer.

## Design (lead decisions; flag disagreement in the report)
Package `contrib/deepsignal/eez_mode/`:
- **Boundaries** (`boundaries.py`): load GeoJSON (Polygon and MultiPolygon, lon-lat order) or GML
  (`gml:posList` and `gml:coordinates`, stdlib `xml.etree`), as downloaded from Marine Regions. Keep each
  feature's id (`MRGID` when present), name and sovereign. Holes are honored. Polygons crossing 180 degrees
  arrive split at plus or minus 180 in Marine Regions data; support that, and test it.
  `prepare(src, clearance, bbox_pad_deg=5) -> cache` writes a compact `eez_cache.json` holding only the
  zones named in the clearance record plus any zone touching the padded cruise bounding box. It also
  records the source file sha256 and its stated version. After that the system runs fully offline. No
  download code in v1: the docs give the Marine Regions download steps, done once ashore.
- **Clearance record** (`clearance.yaml`, example `contrib/deepsignal/configs/eez_mode_example.yaml`):
  ```yaml
  cruise_id: RR2205
  home_zones: [8456]                 # MRGIDs where no clearance is needed (flag state)
  zones:
    - {mrgid: 8467, name: "Example EEZ", clearance: granted, permit: "NOTE-123", valid_from: 2022-04-02, valid_to: 2022-04-20}
    - {mrgid: 8470, name: "Other EEZ", clearance: none}
  default_clearance: none            # any zone not listed
  instruments:                       # logger name -> action where clearance is not granted
    em124:   {uncleared: stop}
    adcp150: {uncleared: stop}
    tsg:     {uncleared: quarantine}
    met:     {uncleared: log}      # navigation and safety data keep logging
  default_action: quarantine         # loggers not listed
  buffer_nm: 2                       # act this far before the line
  prealert_nm: [24, 12, 6]           # warnings at these distances, and at 60 and 15 min ETA
  ```
  Actions map to logger configs: `log` = the logger's current mode config, `quarantine` =
  `<logger>-quarantine` (must exist; check reports it when missing; it writes to a quarantine path that
  #116 and transfers exclude), `stop` = `<logger>-off`. A granted zone outside its `valid_from` to
  `valid_to` counts as not granted.
- **Pinned geometry** (implement exactly; spherical earth R = 6371008.8 m, 1 nm = 1852 m):
  - Containment: ray casting in the lon-lat plane (that is how the polygons are defined), ring vertices as
    given, a point inside an outer ring and outside its holes.
  - Distance to boundary: the minimum over every edge of the great-circle distance from the point to the
    edge. For edge A to B and point P: d13 = angle A-P, t = bearing(A,P) - bearing(A,B). If cos t < 0 the
    distance is d13. Else dxt = asin(sin d13 sin t) and dat = acos(cos d13 / cos dxt); if dat > angle A-B
    the distance is angle B-P, else |dxt|. Multiply by R. Angles use haversine; bearing uses atan2.
  - Speed: bounding-box prefilter per polygon part, padded by the largest alert distance. Edges are only
    evaluated for candidate parts. Checks run at most `check_interval_s` (default 1 s).
  - Test vectors (a 1 degree square, corners lat-lon (0,0) (0,1) (1,1) (1,0); tolerance 0.01 m):
    (0.5,0.5) inside 55595.423 m; (0.5,1.5) outside 55595.423; (-0.25,0.5) outside 27798.770;
    (0.5,-0.1) outside 11119.085; (2,2) outside 157225.649; (0.999,0.5) inside 115.428.
    Square (60,10) to (61,11): (60.5,10.5) inside 27377.275; (60.5,11.2) outside 10950.999;
    (61.1,10.5) outside 11016.644.
  - ETA to boundary = distance / speed over ground, from the configured SOG field. No ETA under 0.5 kn.
- **State machine** (`EEZModeTransform`): inputs are the position, SOG and COG fields. It emits CDS fields
  `eez_state` (`outside`, `approaching`, `inside_cleared`, `inside_uncleared`, `unknown`), `eez_zone`,
  `eez_inside` (bool, for #116), `eez_distance_nm`, `eez_eta_min`, `eez_override`, and, on any change in a
  logger's required action, `set_active_logger_config <logger> <config>` strings for
  `LoggerManagerWriter`.
  - Entering: the action applies once the ship is within `buffer_nm` of an uncleared zone, or inside it.
  - Leaving: hysteresis. The ship must be outside and more than `buffer_nm + 1` nm away for 5 minutes
    before normal configs return.
- **Fail safe**: no valid position for `position_timeout_s` (default 60), or a position that fails sanity
  checks (|lat| <= 90, |lon| <= 180, jump implying more than 40 kn), sets `eez_state: unknown`.
  - Unknown applies the strictest action of the zones within `prealert_nm[0]` of the last good position.
  - With no last good position, or with any uncleared zone within that range, every logger takes its
    `uncleared` action.
  - The docs state the tradeoff plainly: a GPS outage near a foreign EEZ stops or quarantines science
    logging.
- **Override** (`override.py` and CLI `override set --reason "..." --by NAME --hours 2`): forces `log` or
  `stop` for named loggers or all. It needs a reason and a name, and expires (default 2 h, at most 24 h).
  It shows in `eez_override` and the banner. The console and MCP call `set_override(dict)`; nothing else
  can change state.
- **Audit** (`audit.jsonl`, append-only): every state change, every pre-alert, every config command
  sent, every override set and expired, and every period of position loss, with UTC time, position, zone,
  distance and clearance reference.
  - `python -m contrib.deepsignal.eez_mode report audit.jsonl` prints the crossings table for the cruise
    report: zone, entered, left, hours inside, actions per logger, overrides with reasons.
  - Records with kind `eez` go to #133 for Sealog.
- CLI: `prepare`, `check <clearance> <cache>` (checks every logger has its quarantine and off configs in
  the cruise definition when given `--cruise`), `where LAT LON` (zone, inside, distance, what each logger
  would do), `report`.
